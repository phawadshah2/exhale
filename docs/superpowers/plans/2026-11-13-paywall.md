# Paywall implementation plan

> Run with the `execute-plan` skill (project rule), one task at a time: failing test, code,
> passing test, `fvm dart format .`, `fvm flutter analyze --fatal-infos`, that task's
> tests, commit. Steps are checkboxes.

**Goal:** a hard paywall after the plan reveal, a welcome-back reveal for an unpaid plan, a
locked screen when access ends, and Restore and Manage in Settings, all checked on the
device through StoreKit 2.

**Architecture:** a new `lib/features/paywall` feature. One `StoreRepository` hides
StoreKit; a sealed `Access` is resolved from its transactions, cached in settings for
offline starts, held in an `accessProvider`, and enforced by a go_router redirect. The
screens are plain Riverpod widgets fed by a pure `paywallContent()` function.

**Tech stack:** Flutter 3.47.2, Riverpod 3 (hand-written), get_it, drift (schema v12),
go_router, `in_app_purchase` + `in_app_purchase_storekit` 0.4.17 (StoreKit 2 wrappers).

**Spec:** `docs/superpowers/specs/2026-11-13-paywall-design.md`. Designs:
`design/10._paywall/`. Branch `feat/paywall`.

## Global constraints

- Product ids: `com.phawadshah.exhale.annual`, `.monthly`, `.lifetime`. Prices only from
  StoreKit's `displayPrice`; nothing hard-coded.
- No data leaves the phone: no analytics, no server, no third-party SDK.
- The billed amount is the largest price on the paywall; no per-month figure for Annual.
- Every string for the paywall, locked sheet and subscription card lives in
  `PaywallCopy`; the two welcome-back lines in `OnboardingCopy`. Exact copy is in the spec
  (§9 to §12) and is not to be reworded.
- iOS look: `AppIcons`, `GlassSurface` with the Reduce Transparency fallback,
  `showAppSnackBar`, no ripples, haptics, 44 pt targets, light and dark, text to 200%.
  Colours only from the theme (`context.exhale.emphasis` for fills).
- Repositories return `Result`; providers read from `sl`. No `riverpod_generator`.
- Ask Fawad before `pub get` (Task P3). Codegen may run without asking.
- The only file that imports the plugin is
  `lib/features/paywall/data/storekit/storekit_gateway.dart`.

## Review focus

Conditions the spec implies that are most likely to bite; each has a test in its task.

1. StoreKit never answers at startup: the app still opens within 3 s, from the cache or
   on the paywall (P4).
2. A purchase finishes outside the paywall (Ask to Buy approved later, a renewal, a
   refund): access changes without a relaunch (P4, P5).
3. Access ends while the app is in the background: on resume the user is on the locked
   screen, wherever they were (P5).
4. A saved plan that already has logs and was never paid (TestFlight testers): straight
   to the paywall, and the plan's dates are untouched (P5, P6).
5. The stat's inputs are odd: no price, a currency that is not the storefront's, a daily
   spend of zero, a number of days longer than the offer's period: the stat hides, nothing
   divides by zero (P7).

**Consumes:** P1. **Produces:**

```dart
class Offer { final PlanKind plan; final String displayPrice; final double price;
              final String currencyCode; final String currencySymbol; final bool trialEligible; }
enum PurchaseOutcome { purchased, cancelled, pending }
abstract interface class StoreRepository {
  Future<Result<List<Offer>>> loadOffers();          // annual, monthly, lifetime, in that order
  Future<Result<Access>> currentAccess();
  Future<Result<PurchaseOutcome>> purchase(PlanKind plan);
  Future<Result<void>> restore();
  Future<Result<void>> manageSubscriptions();
  Stream<void> get changes;                          // a transaction arrived or changed
}
abstract interface class StoreKitGateway {           // thin, no logic; PluginStoreKitGateway implements it
  Future<List<SK2Product>> products(List<String> ids);
  Future<bool> isIntroEligible(String productId);
  Future<SK2ProductPurchaseResult> purchase(String productId);
  Future<List<SK2Transaction>> currentEntitlements();
  Future<List<SK2Transaction>> transactions();
  Future<List<SK2Transaction>> unfinished();
  Future<void> finish(int id);
  Future<void> sync();
  Future<void> showManageSubscriptions();
  Stream<void> get updates;
}
class FakeStoreRepository implements StoreRepository {   // in lib: tests and debug walks use it
  FakeStoreRepository({Access access, List<Offer>? offers, bool offline});
  factory FakeStoreRepository.entitled();                 // Lifetime
  Access access; bool offline; PurchaseOutcome nextOutcome; Failure? nextFailure; Access? restoreFinds;
  int purchaseCalls; void emitChange();
}
```

- [x] The gateway maps one to one onto `SK2Product.products / isIntroductoryOfferEligible /
  purchase`, `SK2Transaction.currentEntitlements / transactions / unfinishedTransactions /
  finish`, `AppStore().sync / showManageSubscriptions`. For `updates`, read
  `in_app_purchase_storekit`'s `in_app_purchase_storekit_platform.dart` in the pub cache
  first and use what it wires in StoreKit 2 mode (`InAppPurchase.instance.purchaseStream`,
  mapped to `void`); note the choice in a comment.
- [x] Tests (fake gateway): three products → three offers in order with StoreKit's
  `displayPrice`, `price`, currency code and symbol; `trialEligible` only on Annual, from
  `isIntroEligible`; fewer than three products or a `PlatformException` →
  `FailureResult(StoreFailure())`; `currentAccess` maps ids and ISO dates into
  `StoreTransaction`s, ignores unknown ids, and returns `resolveAccess`; purchase `success`
  → finishes every unfinished transaction, returns `purchased`; `userCancelled` →
  `cancelled`; `pending` → `pending`; `unverified` → `StoreFailure`; any call that takes
  over 10 s → `StoreFailure`; `restore` calls `sync`; a gateway update finishes every
  unfinished transaction, then emits on `changes`.
- [x] Implement; register `StoreRepository` in `initPaywallDependencies(sl, store)`.
- [x] Commit `feat(paywall): add the StoreKit 2 store repository`.
- Done with two changes: the plugin sends dates as millisecond strings, not ISO; the 10 s
  timeout covers `loadOffers` and `currentAccess` only, since purchase, restore and manage
  wait on a sheet the user may keep open. `FakeStoreRepository` also counts
  `restoreCalls` and `manageCalls` (P10 needs them).
